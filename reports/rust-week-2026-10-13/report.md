## Что исполняется

Закрытая автономная неделя в RAM исполняет реальные фазы текущих правил: динамические склады, прибытия/труд/профессии/миграцию, открытие бюджета, инвестиции, выбор и оборотный капитал кустарей, зарплату служб, содержание рабов, раннюю еду, строителей и производство, стройку, реальные продажи/рынок/потребление, запасы и доставку, госзакупки, распределение доходов и историю труда. Финальные операции объясняют деньги, запасы/грузы, людей и труд; +7 дней/один revision публикуются только после успеха. Повтор запроса возвращает подтверждённый результат без новых платежей и перехода даты.

Фазы дают имена и времена. Текущий CLI по-прежнему запрещает полный мир до проверки сохранения и самостоятельного запуска; `--inspect` остаётся read-only. Новые EXE установлены в `bin`, предыдущие сохранены в `work/rust-week-2026-10-13/bin-before`. Источник SQLite и рабочий runtime не изменялись. Подтверждён workers1, RAM; native heap limit не реализован.

## Итоговое независимое ревью и четыре исправления

Один свежий независимый reviewer проверил39 исходных изменений и воспроизвёл четыре Important дефекта; один проход исправлений, без повторного ревью. Полный отчёт: `work/rust-week-2026-10-13/final-review.md`; разрешение: `review-resolution.json`. Каждый дефект воспроизведён тестом RED до исправления, затем GREEN.

1. **Оборотный капитал отсутствовал как операция.** Открытие только завершало старую переналадку, оставляя личные1000 при требуемом business reserve500. Теперь реальные деньги переводятся в оборотный кошелёк, общий владелец не финансирует две фирмы одним рублём, principal распределяется с последним остатком. Активным возвращается лишь лишний лично внесённый капитал; неактивная накопленная прибыль облагается текущим налогом, отдельно возвращается principal. Разрешённая выгодная стартовая переналадка оплачивается фактическими личными деньгами, её стоимость не превращается в principal. Пять случаев сверены с `artisan-working-capital.cjs` по всем операциям и метаданным предприятий. Профиль спроса сохраняется; публичный payload не даёт права на такой перевод.
2. **Переход ПОПа не попадал в признание доходов.** База запасов правильно фиксировалась до труда, но replay операций пропускал cohort transfer; при реальном grain1 возникал `Invalid contribution inventory delta`. Теперь подтверждённые операции mobility и открытия кустарей включены в настоящий порядок истории; начальная база не сдвинута. Регрессия показывает полную неделю со сменой профессии и реальным потреблением прежнего запаса.
3. **Терялась обязательная подистория.** Удаление profession/migration receipts не замечалось недельным proof. Теперь проверяются отдельные авторитетные квитанции, единственность и совпадение с mobility wrapper, а также cohort evidence. Удаление, изменение или дубль отклоняется без записи.
4. **Новый ID обходил откат header.** Сохранив прежние receipts, можно было вернуть date/revision назад и выполнить новую неделю в тот же интервал. Теперь проверяется непрерывность завершённой цепочки и точное совпадение header с её концом до первого callback новой недели. Четыре разновидности подмены отклоняются; настоящий следующий ход и точный исторический replay сохранены.

RED/GREEN логи: `review-red.txt`, `review-capital-release-red.txt`, `review-capital-bootstrap-red.txt`, `review-mobility-history-red.txt`, `review-mobility-history-green.txt`, `review-capital-green.txt`, `review-capital-source-final.txt`. Первые два неудачных вызова Gemini CLI упёрлись в перенаправление/лимит длины аргумента; короткий вызов завершился exit0/SUCCESS. Его краткая карта финансовых движений проверена по источнику. Предполагаемые им «дефекты правил» не применялись: они не доказаны и меняли бы согласованный баланс.

## Решения реализации

- Объединённый старый budget API исполняет открытие/службы в одном private OperationSession; отдельные стадии дают те же экономические операции. Цена неверного решения — нарушение порядка платежей; подтверждены дифференциальные тесты.
- Новые счета публикуются по уже назначенному внутреннему ID, без перестановки старых или перенумерации. Цена ошибки — неоднозначное связывание; тесты денежных адресов и ссылок сохранены.
- Shared owner проверяется отдельными purpose-кошельками и реальными handoff бюджет/инвестиции/строители, без придумывания нескольких классов для одного ПОПа. Цена пробела — непокрытый иной контракт; текущие реальные контракты проверены.
- Source oracle использует обычную array миниатюру без перевозки; неполный active/COW контекст исключён. Цена — отсутствие доказательства RAM-паритета полного JS мира; это прямо остаётся непроверенным.
- Явный пустой список приоритетов сохраняется отдельно от отсутствия настройки. Source comparison задаёт обеим сторонам один список. Цена ошибки — скрытая смена спроса; пустой список закреплён регрессией.
- Профиль открытия капитала учитывается и хранится в closed receipt, простой старый API использует обычный профиль. Цена ошибки — иная потребность в капитале; сохранение/несовпадение профиля проверено.
- До самостоятельного checkpoint/runner полный CLI остаётся запрещён; detached recipes не являются неделей. Цена — пользователь ещё не может запустить полный мир этим EXE; следующий этап закрывает этот явный пробел.
- Полный property graph остаётся «нет измерения», хотя закрытые фазы проверяют свои операционные права. Цена — невыявленный дефект исходной собственности; следующий fullworld audit обязан отделить его от ошибок расчёта.
- При отсутствии Git сохранены before snapshot/manifest и все воспроизводимые проверки; рабочая база не подменяется. Цена — нет Git-истории этих изменений; фактические хеши и копии приложены.

Отложенных minor findings по итоговому ревью нет.
