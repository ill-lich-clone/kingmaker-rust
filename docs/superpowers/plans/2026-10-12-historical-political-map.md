# Historical Political Map Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans or superpowers:subagent-driven-development to implement this plan task-by-task after the user's review and execution-method choice. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Дать автору автономную политическую карту Тейванкаля по годам −2500…361 с подписями, карточками и таймлапсом, открываемую двойным кликом без экономики.

**Architecture:** Локальный Python-инструмент готовит компактную историю и статическую топологию из книги и существующих контуров. Обычные браузерные JS-модули разрешают выбранный год, фильтруют заранее подготовленные границы и управляют одним таймером. Canvas 2D использует готовые контуры и камеру; весь просмотрщик поставляется в переносимой папке `history-map`.

**Tech Stack:** Python 3.12, только стандартная библиотека (`zipfile`, XML, JSON, base64, struct, hashlib, unittest); обычные HTML/CSS/JavaScript, Canvas 2D, существующие `provinces.js` и `camera.js`; Node 24 `node:test`/`assert`; имеющийся Playwright для браузерной проверки. Новых библиотек и Cargo-зависимостей нет.

**Spec:** [2026-10-12-historical-political-map-design.md](../specs/2026-10-12-historical-political-map-design.md), утверждена автором 12 октября 2026.

## Global Constraints

- Год: целое число от −2500 до 361 включительно; 0 — существующий год мира. Периоды включают обе конечные даты.
- Начальный год — 361; начальный шаг — 10 лет; начальная скорость — 5 показов года в секунду.
- Шаги: 1, 5, 10, 25, 50, 100 лет. Скорости: 1, 5, 10 показов года в секунду.
- `nextYear = min(currentYear + step, 361)`; кадр 361 показывается и останавливает таймлапс. Пуск из 361 начинает повтор с −2500.
- Ручной ввод, пауза и скрытие вкладки отменяют единственный активный таймер. Возврат во вкладку не возобновляет воспроизведение автоматически.
- Открытие по `file://`, все активы внутри `history-map`; нет сервера, CDN, внешних шрифтов, сетевых запросов или `fetch(file:)`.
- Номера провинций, их контуры и система координат сохраняются. География фиксирована по существующей карте; статус Гудада меняется по книге, без перемещения островов.
- Источник — `D:/груз/teyvankal_province_history_-2500_361.xlsx`; книгу, её формулы и авторские сведения не изменять.
- Не подключать `province-data.js`, Kingmaker bootstrap/client, SQLite, экономические панели, расчёт ходов или игровые API. Экономические правила, настройки, нормы и бюджетные расходы сохраняются.
- `data/kingmaker/runtime.json` остаётся единственным выбором базы и кампании игры. Нового игрового мира и миграций не создавать.
- Окраска по прямому владельцу; сюзерен показан отдельно. Вода и нейтральные категории не объявляются суверенными государствами. Существующие совпадающие цвета палитры сохраняются.
- Надпись «Исторические границы — черновая реконструкция» видна постоянно. Экспорт видео, GIF и снимков в эту версию не входит.

## Review Focus

1. Пустое поле, пробелы, дробь и `NaN` не превращаются в допустимый год 0; ручной ввод ставит таймлапс на паузу и сохраняет последний кадр. Тесты задачи 2/4/5.

### Контракт данных

`HistoryData = {schema:1, range:[-2500,361], owners, strings, provinces}`. Владелец: `{id, code, name, category, color}`; провинция: `{id,name,center,periods}`. Период — `[from,to,ownerIndex,suzerainTextIndex,landStatusTextIndex,periodNameTextIndex]`; индексы ссылаются на `owners`/`strings`. `-1` у сюзерена означает отсутствие значения; `-1` у имени означает совпадение с именем справочника. Различающееся имя периода сохраняется. Вся новая генерация и JS используют этот один контракт.

`GeometryIndex` сохраняет `map_id,width,height,cell_size,grid,groups,records` без экономических полей; относительные пути групп заменяются на `assets/province-geometry/...`. `Topology = {segments, adjacency, metrics}`: сегмент `[x1,y1,x2,y2,provinceA,provinceB]`, `provinceB=0` для внешнего края; метрики содержат площадь с вычетом отверстий и проверенные точки внутри суши. Названия и авторские центры не заменяются вычисленными точками подписи.

`ResolvedProvince = {id,name,ownerId,ownerName,suzerain,landStatus,color,sovereign}`. `Snapshot = {year,provinces:Map<number,ResolvedProvince>}` содержит 1621 неморскую провинцию; море получает отдельную водную карточку по геометрии. Нейтральность определяется категорией и явными техническими ID из книги, а не отсутствием известного цвета.

## Самопроверка плана и передача

Каждый контракт спецификации имеет владельца: источник/геометрия/топология — задача 1; даты и принадлежность — 2; границы и названия — 3; таймлапс — 4; навигация, карточка, автономность, ошибки и визуальный результат — 5. Процедуру воспроизведения сверять с Mermaid-схемой в спецификации и обновлять вместе с любым согласованным изменением её правил.
